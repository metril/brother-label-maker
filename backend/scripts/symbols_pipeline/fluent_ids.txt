# Fluent System Icons curated id list (backend/scripts/symbols_pipeline)
#
# Source: @fluentui/svg-icons@1.1.334 (npm), icons/<id>_24_filled.svg,
# native viewBox "0 0 24 24". FULL SET (unlike Material/Phosphor's
# hand-trimmed subsets -- same "exhaustive, not curated-down" approach
# lucide_ids.txt's own header documents for that source): every one of the
# 2490 canonical `<id>_24_filled.svg` files directly under icons/ in this
# pinned version -- deliberately NOT the other ~146 files matching
# `icons/<locale>/<id>_24_filled.svg` (e.g. icons/ar/*, icons/he/*): those
# are RTL-mirrored duplicates of an id already listed here under the exact
# same base name (Fluent ships them for a handful of directional icons
# whose glyph needs to flip for Arabic/Hebrew layout), not additional
# icons, so including them too would just duplicate content under a
# colliding id, not add any (the exact same "excluded, byte-identical
# geometry under a name already listed" reasoning lucide_ids.txt's header
# gives for excluding Lucide's old-name alias files). Every other size
# variant (_16_filled, _20_filled, _28_filled, _32_filled, _48_filled) and
# every _<size>_regular (outline) variant are also NOT this project's
# concern -- only the 24px filled style. fetch_fluent.py strips the
# `_24_filled` suffix for the manifest id (e.g. "access_time_24_filled.svg"
# -> "fluent_access_time").
#
# Format: same convention as material_ids.txt/phosphor_ids.txt/
# lucide_ids.txt/tabler_ids.txt/remix_ids.txt/bootstrap_ids.txt --
# '#'-prefixed lines are comments, a '# category: <bucket>' line sets the
# manifest `category` for subsequent ids until the next such marker. One
# bare Fluent icon id per line (the filename under icons/, without the
# `_24_filled.svg` suffix; Fluent's ids are already underscore-separated
# natively, e.g. "battery_charge" -> manifest id "fluent_battery_charge").
#
# Category mapping rule: Fluent ships no per-icon category/tag metadata at
# all (unlike Tabler's icons.json) -- categorized via
# common.classify_by_keyword(), the same shared priority-ordered
# electrical/network/av/arrow/safety token-set walk fetch_bootstrap.py uses
# directly and fetch_tabler.py uses as ITS fallback, applied to each icon's
# own id tokens (underscore-split). A small hand-picked override list on
# top (the same escape hatch lucide_ids.txt's own header documents
# needing):
#
#   - "vehicle_cable_car" -> misc (the same "cable-car is a vehicle, not
#     electrical wiring" false positive lucide_ids.txt's own header
#     documents for an identically-named id on a different source).
#   - The 9-id "_lightning" suffix family (arrow_forward_down_lightning,
#     comment_lightning, content_view_gallery_lightning,
#     document_lightning, folder_lightning, notebook_lightning,
#     table_lightning, text_column_one_wide_lightning,
#     text_grammar_lightning) -> misc. Fluent uses a small lightning-bolt
#     badge on an otherwise-unrelated base icon as its own UI convention
#     for "quick/AI-powered action" (a document/folder/table icon with a
#     speed badge, not an icon about electricity), unlike Bootstrap's bare
#     "lightning"/"lightning-charge" (genuine electricity icons) or
#     Tabler's "bolt" (an actual lightning-bolt pictogram) -- every id
#     ending in "_lightning" in this pinned version is one of these badge
#     variants, none a literal electricity icon.
#
# (Fluent's actual weather icons -- weather_rain, weather_snow,
# weather_partly_cloudy_day, etc. -- all use a "weather_" prefix rather
# than a bare "cloud" token, so they land misc without needing the
# cloud-vs-weather override bootstrap_ids.txt's header documents needing
# for that source's differently-named cloud-<weather> family; verified by
# hand against this pinned version's full id list.)
#
# Category distribution at generation time: electrical 20, network 55,
# av 179, arrow 231, safety 88, misc 1917.
