# Tabler curated id list (backend/scripts/symbols_pipeline)
#
# Source: @tabler/icons@3.46.0 (npm), icons/filled/<id>.svg, native viewBox
# "0 0 24 24". FULL SET (unlike Material/Phosphor's hand-trimmed subsets --
# same "exhaustive, not curated-down" approach lucide_ids.txt's own header
# documents for that source): every one of the 1054 icons under
# icons/filled/ in this pinned version. Tabler's own MIT license and repo
# already separates "filled" from "outline" as a full parallel style set
# (unlike Phosphor's multiple weights, there's no further trimming
# question here) -- outline/*.svg is NOT this project's concern, only the
# already-filled variant is (see fetch_tabler.py's module docstring for why
# these SVGs still need fetch_tabler.py's multi-path merge: every filled
# icon ships an invisible fill="none" bounding-box <path> ahead of the real
# glyph path(s), and ~230 of the 1054 have 2+ real glyph paths beyond that).
#
# Format: same convention as material_ids.txt/phosphor_ids.txt/
# lucide_ids.txt -- '#'-prefixed lines are comments, a '# category: <bucket>'
# line sets the manifest `category` for subsequent ids until the next such
# marker. One bare Tabler icon id per line (the filename under
# icons/filled/, without .svg; native hyphens, e.g. "arrow-badge-left" --
# fetch_tabler.py converts to underscores for the manifest id,
# "tabler_arrow_badge_left").
#
# Category mapping rule: Tabler ships real per-icon metadata (icons.json,
# `category` + free-text `tags` per icon) -- this file's categories start
# from that metadata rather than a from-scratch keyword-map, per the
# brief's "from package metadata if the tarball has categories/tags"
# guidance, in this fixed priority order:
#
#   1. icons.json's own `category` == "Arrows" -> arrow, unconditionally.
#      The only one of Tabler's ~33 native categories with a clean 1:1
#      mapping onto this project's 7 buckets (100 icons; ~9 of them, e.g.
#      "swipe-down"/"transition-left"/"download", have no
#      arrow/chevron/caret token in their bare id at all, so this
#      category-level signal is load-bearing, not just a shortcut).
#   2. icons.json's own `category` == "Brand" -> misc, unconditionally.
#      Company logos/trademarks (e.g. brand-spotify, brand-youtube,
#      brand-tiktok) whose own marketing tag lists mention
#      "video"/"music"/"streaming" etc. would otherwise get pulled into av
#      by coincidence -- a brand logo isn't a functional av/network/
#      electrical icon regardless of what its promotional copy says.
#   3. Otherwise: common.classify_by_keyword() (the same shared
#      priority-ordered electrical/network/av/arrow/safety token-set
#      walk fetch_bootstrap.py/fetch_fluent.py use directly) over the
#      icon's OWN id tokens (hyphen-split) ONLY -- deliberately NOT
#      unioned with icons.json's `tags` array. A spike that DID fold in
#      `tags` found Tabler appends a repeated per-top-level-category
#      "flavor" suffix to every icon's tag list (e.g. every "Document"
#      icon ends with ['file','paper','text','record','information'],
#      every "Media"/"Photography"/"Badges"/"Games"/"Brand" icon ends with
#      ['content','entertainment','multimedia','broadcast','audio'], every
#      "System" icon ends with ['control','operation','function',
#      'interface','management']) -- boilerplate, not real per-icon
#      signal, that happened to overlap this project's own keyword sets
#      heavily enough to misclassify ~150 unrelated icons (playing cards,
#      pacman, golf, generic clipboard/file icons, brand logos, an entire
#      12-icon digital-clock-face family via a generic "alarm" flavor
#      word, alert-hexagon/alert-square/alert-square-rounded via a generic
#      "signal" flavor word landing them in network ahead of the safety
#      bucket their real warning/caution/danger tags actually mean).
#      id-tokens-only trades a little recall (a few thematically-domain
#      icons without a literal token, e.g. "brightness"/"contrast" for
#      camera settings, default to misc rather than av) for materially
#      fewer false positives -- the right tradeoff for an unreviewed
#      full-set import.
#   4. A small hand-picked override list on top (the same escape hatch
#      lucide_ids.txt's own header documents needing): "device-heart-monitor"
#      would land av via its "monitor" token (a medical vital-signs
#      display, not an av screen) and the whole "play-card"/"play-card-1"
#      .."play-card-star" family (16 playing-card icons) would land av via
#      "play" (correct for e.g. "player-play", a false positive for a
#      literal playing card) -- both forced to misc.
#
# Category distribution at generation time: electrical 13, network 6,
# av 19, arrow 102, safety 23, misc 891.
