# Lucide curated id list (backend/scripts/symbols_pipeline)
#
# Source: lucide-static@1.28.0 (npm), icons/<id>.svg, native viewBox
# "0 0 24 24" (stroke-based: multiple path/circle/rect/line/polyline
# elements, fill="none" stroke="currentColor" stroke-width="2" -- see
# fetch_lucide.py's module docstring for why this categorically doesn't fit
# common.extract_single_path_d's single-verbatim-<path> assumption the way
# Material/Phosphor's already-filled source icons do).
#
# fetch_lucide.py converts every id's stroke-based source SVG into a single
# filled <path> via a batched `npx oslllo-svg-fixer@6.0.1` run (a
# rasterize-then-potrace stroke outliner -- a LOSSY transform, unlike
# Material/Phosphor's verbatim-path normalization; see LICENSES.md's Lucide
# section and fetch_lucide.py itself for detail) before applying this
# project's usual viewBox="0 0 24 24" wrap. Unlike Material (960-unit) or
# Phosphor (256-unit), NO coordinate transform is needed afterward: Lucide's
# native viewBox already IS "0 0 24 24", and oslllo-svg-fixer's traced path
# coordinates come back in that same space.
#
# Format: same convention as material_ids.txt/phosphor_ids.txt -- '#'-prefixed
# lines are comments, a '# category: <bucket>' line sets the manifest
# `category` for subsequent ids until the next such marker. One bare Lucide
# icon id per line (the filename under icons/, without .svg; native hyphens,
# e.g. "arrow-right" -- fetch_lucide.py converts to underscores for the
# manifest id, "lucide_arrow_right").
#
# FULL SET (unlike Material/Phosphor's hand-trimmed subsets -- see the brief:
# Lucide is meant to be exhaustive, not curated-down): every one of Lucide
# 1.28.0's 1756 CURRENT icons, i.e. every key in the npm package's own
# tags.json / icon-nodes.json -- deliberately NOT every file under icons/
# (2007): the extra 251 are old-name aliases upstream keeps for backward
# compat (e.g. "alert-circle" is now "circle-alert") that are byte-identical
# geometry to an icon already listed here under its current name, so
# including them too would just duplicate content under a second id, not add
# any. tags.json's key set was verified to be a strict subset of icons/'s
# filenames (every key has a same-named .svg) -- fetch_lucide.py's
# missing-file skip guard, shared with fetch_material.py/fetch_phosphor.py,
# stays in place regardless as the general safety net.
#
# Category mapping rule: the npm package ships no ready-made category/bucket
# metadata -- only a free-text search `tags` array per icon in tags.json (a
# many-keyword soup, e.g. "activity"'s tags span medical/audio/seismic/
# fitness -- not a single bucket signal). The upstream lucide-icons/lucide
# GitHub repo DOES carry a per-icon `categories` field (icons/<id>.json), but
# that lives outside the pinned npm package on an unpinned branch, so using
# it here would make this file's category assignment depend on an unrelated,
# unpinned moving target rather than the one pinned tarball fetch_lucide.py
# downloads -- so, per the brief's documented fallback, this file was
# generated by a deterministic keyword-map on each id's own hyphen-separated
# tokens instead: electrical/network/av/arrow/safety token sets (a small,
# hand-picked list per bucket -- e.g. network's includes "wifi", "bluetooth",
# "router", "signal", "cloud" ...) checked in that fixed priority order
# (first match wins, e.g. "battery-warning" lands electrical via "battery"
# before safety's "warning" is even checked); no match defaults to misc.
# A handful of hand overrides sit on top where a bare token would be wrong
# (e.g. "cable-car" is a vehicle, not electrical wiring -- "cable" alone is
# excluded for that one id) or needs two tokens together that don't split
# into a single matching token (e.g. "circuit-board", "alarm-smoke"). This is
# an automated, reviewable-in-bulk categorization appropriate to a full
# ~1750-icon set -- not hand-curated icon-by-icon like Material/Phosphor's
# lists, which is exactly what the brief asks this file to be.
#
# Category distribution at generation time: electrical 25, network 68, av 74,
# arrow 143, safety 51 (newly populated -- unused by every other source),
# misc 1395 (the default catch-all: general single-object/UI iconography
# that doesn't anchor to any of the five domain buckets above).
