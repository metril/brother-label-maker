# Remix Icon curated id list (backend/scripts/symbols_pipeline)
#
# Source: remixicon@4.9.1 (npm), icons/<Category>/<id>-fill.svg, native
# viewBox "0 0 24 24". FULL SET of the *-fill.svg variants (unlike
# Material/Phosphor's hand-trimmed subsets -- same "exhaustive, not
# curated-down" approach lucide_ids.txt's own header documents for that
# source): every one of the 1539 `-fill.svg` files under icons/ in this
# pinned version, across all 19 of Remix's own category folders (the
# `-line.svg` outline variants alongside them are NOT this project's
# concern). Every Remix fill icon happens to already be a single <path>
# (verified against the full curated set: fetch_remix.py still runs every
# candidate through the same common.extract_fill_path shared multi-path
# merge fetch_tabler.py/fetch_bootstrap.py/fetch_fluent.py use, since that
# function handles the single-path case too and additionally preserves a
# lone path's own fill-rule -- see its docstring -- rather than adding a
# second, narrower code path that would only ever be exercised by accident
# if a future remixicon release ever ships a multi-path fill icon).
#
# Format: same convention as material_ids.txt/phosphor_ids.txt/
# lucide_ids.txt/tabler_ids.txt -- '#'-prefixed lines are comments, a
# '# category: <bucket>' line sets the manifest `category` for subsequent
# ids until the next such marker. One bare Remix icon id per line (the
# filename under icons/<Category>/, without the `-fill.svg` suffix; native
# hyphens, e.g. "battery-2-charge" -- fetch_remix.py converts to
# underscores for the manifest id, "remix_battery_2_charge").
#
# Category mapping rule: unlike Tabler (per-icon metadata) or
# Bootstrap/Fluent (no metadata at all, keyword-map on the id), Remix ships
# its OWN folder-per-category layout -- a strictly better, human-curated
# signal than guessing from tokens, so this file maps folder name directly
# to one of this project's 7 buckets (coarse: every id in a folder gets
# that folder's single bucket, no per-icon override). Remix's 19 folders:
#
#   Arrows          -> arrow   (unambiguous: directional/navigation icons)
#   Media           -> av      (camera/video/music/broadcast/equalizer --
#                                dominant theme by a wide margin)
#   Device          -> network (dominant theme: wifi/bluetooth/router/
#                                signal/hotspot/nfc/rfid/sim/qr/cast --
#                                despite also holding some battery/cpu/
#                                hardware icons that would individually read
#                                "electrical"/"misc"; a coarse per-folder
#                                rule has to pick ONE bucket, and
#                                connectivity terms are the plurality here)
#   (all other folders: Buildings, Business, Communication, Design,
#   Development, Document, Finance, Food, Game & Sports, Health & Medical,
#   Logos, Map, Others, System, User & Faces, Weather) -> misc (default;
#   each is either genuinely general-purpose (System, Business, Document,
#   Design, ...) or a domain this project's 7 buckets don't have a slot for
#   (Weather, Food, Health & Medical, Logos -- brand marks deliberately not
#   pulled into a functional bucket, same reasoning tabler_ids.txt's header
#   documents for Tabler's own "Brand" category))
#
# Category distribution at generation time: network 96 (Device), av 148
# (Media), arrow 89 (Arrows), misc 1206 (every other folder).
